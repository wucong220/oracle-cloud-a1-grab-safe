# 回滚与停止方案

本次没有真实部署、云端更改、凭据搬运、timer 变更或远程 push，因此当前回滚仅涉及本地源码。不要把旧源码恢复后自动启动，因为原版 DRY_RUN 也会创建实例。

## 本地源码回退

保存本地加固分支与审计报告。Git 中固定基线为 `b6bc5cb20e0d8f5e51e4a4c1691c5573ef3c9e61`；可用 `git show <SHA>:<path>` 查看原文件。若只需比对旧版，在独立 checkout 中读取该 commit，不运行旧 setup/grab，不使用 `git reset --hard` 删除当前工作。也可通过本地 Git revert 加固提交来回退代码，但务必先停用所有启动入口。

## 将来部署后的停止顺序

1. 禁用用户后来明确安装的本工具计划任务或 service，仅停止本工具。不要关闭系统更新、dnf/PCP 或其他服务。
2. 将私有配置改回 DRY_RUN=1、ALLOW_CREATE=0，取消本地审批文件；保留状态目录和 journal。
3. 已发出请求的进程被中断时，把结果视为未知。先读取状态，按所有 compartment 和 operation tag 核对正在启动/运行/停止中的实例；有已知 ID 则 GET。不能根据空列表推断未创建。
4. 保留未知请求的 token 和完整请求在原私有目录，供核对使用；不要贴进聊天、日志、issue 或云盘。不要换 token、删 journal、改名字重发。
5. 若已有实例，本工具的源码回滚不会撤销云资源或费用。任何终止实例、删除 boot volume、改网络/IAM/计费都需要用户另行明确决定，本工具没有删除入口。

若曾在本次审计之前运行过上游 setup，先查操作记录确认哪些 timer 原本启用；不要无差别 enable。需要恢复原服务状态时，只对已证实被旧脚本更改的具体 timer 执行用户确认的恢复。本次没有此类变更，无需恢复 timer。

独立 OCI venv 可在确认本工具已停止后保留或手工卸载；不影响 Codex CLI、用户原有 OCI 安装或私钥。将来如撤销 API Key，必须由用户明确授权并单独处理，不能把删 IAM 凭据当作自动回滚步骤。

状态损坏、磁盘故障、token 过期或未知账单无法核实时，保持停止。没有“强制继续”或自动清理未知意图的安全替代操作。
